# HW12 – временные ряды: temporal split, baseline-модели и GRU-прогноз

## 1. Кратко: что сделано

- Использовался датасет S12-hw-dataset.csv для задачи прогнозирования временного ряда (target).
- Данные были отсортированы по времени и разбиты на train / validation / test в пропорции 70/15/15 без перемешивания.
- Были реализованы и сравнены четыре подхода: B1 — наивный прогноз (последнее значение),B2 — скользящее среднее, B3 — линейная модель Ridge на лаговых и календарных признаках, R1 — нейросетевая модель GRU.
- Лучшим оказался baseline B1 по метрике MAE на validation, поэтому он был выбран для финальной оценки на test.

## 4. Temporal split и признаки

### 4.1. Разбиение по времени

- Использовано разбиение по времени без перемешивания:
- 70% — train
- 15% — validation
- 15% — test
- Разбиение выполнено через индексы датафрейма после сортировки по дате
- Почему random split некорректен: Random split приводит к утечке будущей информации в обучение, так как модель может обучаться на данных, относящихся к будущему относительно validation и test.

### 4.2. Признаки для baseline-моделей

- Какие лаги использовались: 1, 7, 14
- Какие rolling-признаки использовались: rolling mean (7), rolling std (7)
- Какие календарные признаки использовались: day_of_week
- Как обрабатывались пропуски после построения лагов/rolling: после построения признаков использовалось dropna()
- Использовалось ли масштабирование и где именно оно обучалось: не использовалось

## 7. Анализ

Наивный baseline показал лучший результат, что объясняется высокой автокорреляцией временного ряда. Предыдущее значение хорошо предсказывает текущее.Moving average сглаживает шум, но из-за этого хуже реагирует на быстрые изменения, что приводит к ухудшению качества. Ridge-модель с лаговыми признаками учитывает больше информации, однако из-за линейной природы модели не смогла существенно превзойти naive baseline. GRU не показала улучшения качества, вероятно из-за недостаточной настройки гиперпараметров и отсутствия нормализации данных. В ряде заметна сезонность, что подтверждается регулярными колебаниями значений.Возможные источники утечек: использование будущих значений target, некорректное построение rolling-признаков, неправильный split. В данной работе утечки предотвращены за счёт использования shift и temporal split. Выбор модели по validation принципиален, так как test должен оставаться независимым и использоваться только для финальной оценки.

## 8. Итоговый вывод

Для данной задачи наилучшим оказался простой baseline (B1). В задачах с высокой автокорреляцией сложные модели не всегда дают преимущество. Линейные модели с признаками могут давать улучшения, но не всегда значительные. Нейросети (GRU) имеют смысл при более сложных зависимостях или при более тщательной настройке. Главный вывод — корректная валидация временных рядов через temporal split критически важна.
